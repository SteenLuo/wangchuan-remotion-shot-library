# 可积累纠错闭环

目标不是让模型“记住一句提醒”，而是把每次已证实的偏差变成下次自动执行的约束。

## 一次纠错必须留下什么

1. 将偏差归入来源区间、稳定状态、成员/层级、包装/视口/裁切、文字约束、运动通道、方向次数、节拍/周期、相位、组合承接、渲染或发布门禁。
2. 只修改该事实的唯一所有者：来源事实、manifest、motion measurement 或 combination members。不要手改派生汇总文件作为修复。
3. 对结构与绑定错误建立用户项目自己的最小回归测试；测试先证明一个最小变异会触发错误，再证明修复后的真实镜头通过。不能只增加没有执行器的断言名称，也不能用静帧代替连续成片。
4. 若问题只属于一个素材，契约先限定到该序号或镜头族；当另一条镜头出现同一根因，或规则本身可由结构证明为通用时，再提升到共享算法。不要把一次审美偏好直接扩散到所有项目。
5. 在首次复刻或认证模式运行受影响镜头的回归与 QA。普通镜头只检查自身；`carry` 成员检查自身及依赖后缀；无视觉输入变化的政策调整只重跑 QA，不重渲视频。普通认证模板调用不运行这套重型回归。

模板认证与生产调用不在本公开发行范围。不要引用不存在的私人 QA 引擎；首次复刻只运行用户工程里真实存在的验证，并保留成片证据。

## 哈希与状态

用户项目的验证记录至少保存来源、配置与当前视频哈希、技术检查和明确的用户批准；不存在 QA 引擎时不能虚构验证结果。

任一事实、共享规则或审阅成品变化后，受影响批准自动视为 `stale`。Gate 1、Gate 2 分别绑定当前成片 SHA-256；模板认证另绑定组件和运行时指纹，不能复用“这个序号以前通过过”。

外部发布不在公开发行范围，不以历史发布记录代替本次实际视频核验。

## 新来源的增量接入

直接视频、飞书附件或迁移来源到达后，先建立本地稳定序号、不可变来源副本和哈希。仅 `new` 或 `changed` 的序号进入测量、生成和 QA；`unchanged` 保留现有哈希、批准和产物。多窗口并行时，具体镜头窗口只写自己的序号目录，共享机制由一个窗口统一维护。

用户视觉门以正常速度完整成片为主，稳定状态图与同帧板作为证据。内部轨迹报告和回归测试由系统自行完成；只有来源含义确实存在多种合理解释且会改变实现时才向用户询问。

## 知识分层与成熟度

知识按 `craft`（通用专业知识）、`creators/<creatorId>`（博主空间）和单条视频证据分层。项目执行规则是应用这些知识形成的约束，不替代三层知识证据。

单条观察为 `observation`；不同视频重复两到三次才可成为 `candidate_pattern`；多题材/结构成立且无关键反例才晋升 `stable_pattern`。跨博主重复仍只是通用候选，结合行业定义和反例后才能进入 craft。记录样本数和反例，不能把一次审美偏好当稳定作者风格。

## 知识记录字段与来源

每条记录 `creatorId`、`knowledgeId`、`knowledgeType`、具体 claim、sourceSequenceIds、evidenceFrames、sampleCount、confidence、scope、counterexamples、lastValidatedAt 和 implementationMapping。保留当前口播、最小上下文、叙事问题、为什么使用 B-roll/载体/出现时点、注意力顺序、认知与情绪结果，区分 visible_evidence、context_inference 和 personal_judgment。

低置信度学习按：辨识疑点 → 查官方文档/教材/论文/专业来源 → 比较相邻概念与常见实现 → 回原视频再判断 → 当前样本和反例验证。每条实际采用资料保存标题、原始 URL、发布者、资料类型、访问时间、所支持的具体判断和适用范围；搜索摘要只找线索，不能当真值。首次知识获取与后续已有知识调用分开计时。

新增案例沿用可定位的命名空间；迁移目录时更新索引，不复制出多份互相冲突的事实。

## 经验而非过程

Skill 只写可执行经验：触发/不适用条件、可见形态与职责、父级/坐标系/作用域、前后状态与顺序、固定部分/参数/替换依赖、正常速度感知目标、检查与失败条件。不复制日期、返工经过、聊天原话或已废止实现。具体帧、像素、失败成片与实验证据留在项目文件，必要时从主题 reference 精确引用。

过程到主文档、主文档到 Skill 分别核对。每条来源决策须能找到实际入口、详细章节和验证方式；从 Skill 反查来源授权。自动覆盖校验只证明编号、路由和证据可定位，不能替代人工核对语义，也不能证明视觉识别成功。
