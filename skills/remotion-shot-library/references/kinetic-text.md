# 文字识别与花字模板

## 默认执行范围

所有新镜头在来源分析时识别设计文字、标题、标签、价格、数据、文档标题和具有语义的符号。常规底部口播字幕与创作者水印不进入镜头模板。已批准旧镜头不批量迁移；旧镜头一旦发生可见文字或动效改动，必须迁移该镜头全部可见文字槽。

## 四处归属

- `source-record.json.textObservations`：原文、帧段、边界样本、字体形态、字体身份是否可确认、字号与占屏、填充、光影、纹理、表面质感、运动和属性级 `claims`。
- `shot-manifest.json.textSlots`：可替换内容、父层、层级、像素/归一化边界、排版、字体令牌、填充层、效果层、状态和替换 QA 样例。
- `motion-measurement.json.textBehaviors`：行为类型、grapheme/word/line 单位、起止帧、顺序、关键帧、镜头/父容器绑定和替换时序策略。
- `combination-members.json`：只保存跨镜头承接，不复制样式与动作。

不要创建第五份人工维护的文字真相文件。`rebuild-spec.json`、OCR 缓存、模板索引和诊断图均为派生物。

## 观察要求

按属性或一组互相依赖的声明记录证据和置信度；禁止用一个总分覆盖全部文字属性。具体字体无法由像素唯一确认时写明“不确定”，模板渲染仍必须选择一个版本锁定的字体令牌。

至少记录：

- 文字内容与语义角色；
- 边界、占屏、行数、对齐、锚点；
- 字体形态、字重、字号范围、行高、字距；
- 纯色/渐变/纹理填充；
- 描边、硬/软阴影、发光、模糊和混合层；
- 透明度、倾斜/透视、颗粒、掉墨/打印、石材等纹理及其作用范围；
- 出入场、二维像素块聚合、色块覆盖、逐字/逐词、擦除改写、遮罩、镜头主从关系和真实帧节奏。

不能只判断“淡入/溶解”。逐帧检查块的尺寸、数量、空间分布、聚合方向、文字轮廓形成顺序以及是否同时存在失焦到凝实。效果附着于字形时，记录遮罩、父层、z-order 和同步关系；不要拆成无关贴图。

## 实现要求

- T0 使用 DOM/CSS；T1 使用 SVG。Canvas/WebGL 只有在 T0/T1 不足且有明确收益时再增加。
- 使用 `Intl.Segmenter` 分割 grapheme，禁止 `[...text]`。
- 使用 `@remotion/layout-utils` 以真实字体测量，禁止按字符数量估算宽度。
- 溢出策略只能明确缩小、换行后缩小或拒绝；禁止靠 `overflow:hidden` 静默裁切。
- 不得在渲染时运行 OCR，不得把文字、包装和效果烘焙为不可替换位图。

## 文字验证

在参考配置验证字体真实加载、文本容量、基线、父级运动和实际 MP4 中的字形完整性。可见文字变化后重新渲染并复查受影响视觉门；这里不提供模板认证或外部发布入口。
